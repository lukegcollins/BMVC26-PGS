# PREREG — BMVC SLERP rerun (2026-09-29, written before any SLERP-rerun number exists)

## Why
Paired SLERP augmentation (BMVC #629 §Methodology, eq. slerp: L_unif over observed embeddings plus
SLERP(z_r, z_f, τ), τ ~ U(0,1)) was deleted in the 2026-03-11 repo cleanup (d73d1689 / 2d9b3fda).
The `use_paired_slerp_aug` flag and its "Use SLERP aug: True" log line survived, so every reported
BMVC run trained with SLERP **inactive**. That covers the poseidon main runs at 306d5673 (2026-04-22), the hades
ablations and sweeps at e498a86, and the LaCie paper-source snapshot. Verified 2026-09-29 by git grep on all
three. The paper's "+uniformity (+SLERP)" rows are therefore uniformity-only. SLERP was restored in
95d7767a, gated on the same flag, with 7 tests.

## Design
- Configs: `configs/experiments/slerp-rerun/`, generated by `scripts/gen_slerp_configs.py`. Each is the BMVC
  config with only `task_target` and `use_paired_slerp_aug` changed (verified by diff: 2 or 4 lines).
- Metric: the BMVC MEAN-17 video AUC, i.e. `build_table3.py` DATA_17, from the macro-best-validation
  checkpoint (highest `video_auc` in the Lightning filename). Rescored on the full 22-dataset test list.
- April reference: frozen before any rerun in `data/april_bmvc_reference_mean17.csv` (44 runs, same
  picker as build_table3.py).
- Current code (post-2026-09-29): both arms of every comparison run on the same code, data and seed.

## Stage 1 — s42 pilot (6 runs)
{LN, LoRA, GSD-LoRA} × {SLERP on, SLERP off} at s42.
- **Gate (mechanical, `analysis/slerp_readout.py pilot`):** Δ_arm = MEAN17(on) − MEAN17(off).
  **GO** if max_arm |Δ_arm| ≥ 0.5 pp; **STOP** otherwise; **INCOMPLETE** if any of the 6 runs is missing.
  The 0.5 pp threshold is about 1.5–2× the April within-arm seed SD (0.2–0.4 pp).
- **Drift check:** off − April s42 per arm. **DRIFT** if any |off − April| > 1.0 pp, meaning the current code
  or data no longer reproduces April.

## Stage 2 — full (only on GO)
- Main arms at s137 and s1729, on and off: 12 runs.
- SLERP-on for the 5 ablation groups whose configs set SLERP on (ln_opa_unif, ln_no_hardrr, ln_no_small,
  lora_no_gtl, gsd_lora_vbar) × 3 seeds: 15 runs. Their comparator is the April runs.
- **If DRIFT:** also the matched SLERP-off for those 15, because April is then not a valid comparator. That
  adds 15 runs.
- Readout: `slerp_readout.py final`. Report per group × arm the mean ± SD over seeds, the matched paired Δ, and April.

## Readings (fixed now)
- **STOP:** SLERP is not load-bearing at s42 (|Δ| < 0.5 pp in every arm). The BMVC/thesis text should say the
  reported configuration is uniformity-only and that restoring SLERP does not change it.
- **GO + final:** report the 3-seed matched Δ per arm. The sign and size decide whether "(+SLERP)" rows need
  corrected numbers or only a wording erratum. That decision stays with the author and supervisors.
- **DRIFT:** reported regardless of GO/STOP. April numbers can then be compared only through the matched off arm.

Nothing is dropped after a number exists. Failed runs are re-queued, not excluded. Deviations are dated amendments.

## AMENDMENT A1 — 2026-09-30 (written before any SLERP-rerun number exists)

**What happened.** The first pilot launch (2026-09-30 19:41) failed every gate: `num_samples=0`. The BMVC configs read the
`256w_256h_1.3x_32f_insightface` group, which no longer exists on hades or poseidon storage (FF++ has only the 64f and
all-frames groups). Two BMVC-era split names (DFDM, PolyGlotFake at ratio 0-0-100) also no longer resolve, and KoDF is now `KoDF-BM`.

**Change (data only).** Each generated config takes `train_datasets`, `val_datasets`, `test_datasets`, `default_processing_group`
and `scan_mode` from the canonical current **32FA** recipe (`configs/experiments/WACV/generated/dinov3--32FA--s42.yaml`):
- the all-frames group, `scan_mode: balanced` and `frame_num` 32, i.e. 32 frames spread evenly per video, as the old 32f extraction did;
- the same 4 train / 3 val / 22 test log names as BMVC, with KoDF → KoDF-BM.

Every other key stays the BMVC config's (model, loss, optimiser, schedule, epochs, seed). MEAN-17 reads `KoDF` from `KoDF-BM`.

**Consequence for the design.**
- The primary comparison is unchanged and uncompromised: matched SLERP on − off, on the same code, data and seed.
- The April comparison is now confounded by the data path (all-frames sampling vs a separate 32f extraction, KoDF-BM, the
  current loader), so **DRIFT is reported descriptively only**.
- Stage 2 therefore **always** runs the matched SLERP-off arm for the 15 ablation configs (as the DRIFT branch already
  specified). April is never used as a comparator.
- The GO/STOP rule (max |Δ| ≥ 0.5 pp at s42) is unchanged.

**A1 addendum (2026-10-01 ~00:10, still before any number): test-split disclosure.** BMVC read DFDM and PolyGlotFake with
split `0-0-100` (all_test: 7,040 and 14,367 videos). The current resolver (`src/dataset/idm_paths.py`) allows only `72-14-14`
and `0-0-BM` for those datasets, hence the "manifest not found" warnings. The A1 configs use the canonical `0-0-BM`
benchmark_test splits (DFDM 500, PGF 1,260), matching the thesis 22-set protocol. PGF's all_test was never extracted at
all-frames, so April's PGF set cannot be reproduced from the all-frames source in any case. KoDF was already `0-0-BM` in BMVC
(only the log name changes). This touches only the descriptive April comparison. The matched on/off arms share identical test sets.

## AMENDMENT A2 — 2026-10-12 (written before any stage-2 number exists): stage 2 reduced to the 12 main-arm runs

**What is known.** The stage-1 pilot gave **GO** (2026-10-09). Δ on − off at s42 was LN +0.06, LoRA −0.83 and GSD-LoRA −0.62 pp. There was no DRIFT (the off arms are within 0.46 pp of April). No stage-2 run has been started.

**Why reduce.**
- Measured cost is about 12 GPU-h per run: 10–11 h training plus about 2 h for the 22-set rescore. The full stage 2 (12 main-arm + 30 ablation runs) is therefore about 500 GPU-h on the single RTX 4090. That would end around 4 November, after the 31 October thesis evidence freeze.
- The pilot shows that restoring SLERP raises no arm. No reported "(+SLERP)" row would be replaced by a SLERP-on row.
- The ablation groups were all run with SLERP inactive. Their internal comparisons stay valid as uniformity-only comparisons, which is how the thesis now describes them.

**Change.**
- Stage 2 runs only the main arms {LN, LoRA, GSD-LoRA} × {on, off} × {s137, s1729}: 12 runs, about 6 days.
- The 30 ablation-group runs (5 groups × 3 seeds × on/off) are dropped.
- `slerp_readout.py final` reports the 3-seed matched Δ per main arm. It marks the ablation groups as dropped under A2, with their April reference only.

**Unchanged.** The GO reading ("report the 3-seed matched Δ per arm"), the metric (MEAN-17), checkpoint selection, and the rule that failed runs are re-queued, not excluded. Whether the BMVC "(+SLERP)" rows need corrected numbers or a wording erratum stays with the author and supervisors.

## AMENDMENT A3 — 2026-10-19 (post hoc, written before any non-selected checkpoint has a test number): LoRA on − off across each run's saved top-3 checkpoints

This is the third amendment. Both earlier ones are headed "A2" (2026-10-01 and 2026-10-12). It adds a diagnostic and changes nothing above: the stage-2 verdict (`results/slerp_rerun_verdict.md`), its metric and its checkpoint rule stand as reported.

**What is already known (disclosed).**
- Stage 2, selected checkpoints (MEAN-17): LoRA on − off = −0.83 / −0.30 / −0.26 pp at s42 / s137 / s1729, mean −0.46 ± 0.32 pp. On 92.18 ± 0.10, off 92.64 ± 0.42.
- Post hoc analysis I3 (`publication/THESIS_RERUNS/framing_2026-10-19/02_quant_investigations.md`) found:
  - the drop is negative on 12/17 sets;
  - three sets carry 67% of it;
  - s42 dominates;
  - the LoRA runs select early epochs (on 03 / 04 / 04, off 02 / 02 / 03 in the checkpoint file names);
  - SLERP-off selects sharper single-epoch validation peaks (+1.69 pp above neighbouring epochs vs +0.74 pp on);
  - validation over the whole trajectory is on par (median 0.8249 on vs 0.8260 off).
- The validation macro of every saved checkpoint is known, because it is in the file names (the `video_auc` field; save_top_k = 3):

  | run | rank 1 (selected, scored in stage 2) | rank 2 | rank 3 |
  |---|---|---|---|
  | orthoflow_gtl_lora_slerpon_s42 | epoch=03-video_auc=0.8484 | epoch=05-video_auc=0.8478 | epoch=02-video_auc=0.8452 |
  | orthoflow_gtl_lora_slerpon_s137 | epoch=04-video_auc=0.8603 | epoch=03-video_auc=0.8600 | epoch=02-video_auc=0.8523 |

- No rank-2 or rank-3 checkpoint has ever been scored on a test set (checked 2026-10-19: each run's `test/` holds only its rank-1 `rescore_full22_*`).

**Question.** Does LoRA's on − off drop survive a change of checkpoint, or does it depend on which single checkpoint selection picked?

**Design.**
- Score the 12 rank-2 and rank-3 checkpoints above on the stage-2 test list, with the stage-2 scorer and config: `python -m src.cli.test --checkpoint <ckpt> --config configs/experiments/slerp-rerun/<run>.yaml --resume`, fp32.
- Output goes to `training/logs/slerp_lora_top3/<run>/<checkpoint stem>/`. This is outside the run directories, so neither `slerp_readout.py` (which reads `test/rescore_full22_*`) nor any stage-2 path sees these numbers.
- Rank-1 numbers are the committed stage-2 rescores.
- Driver: `publication/THESIS_RERUNS/scripts/run_slerp_lora_top3.sh` (queue job 25). Readout: `publication/THESIS_RERUNS/analysis/slerp_lora_top3_readout.py`.

**Gate (before any rank-2/3 number is read).** The current pipeline re-scores the rank-1 checkpoint of `orthoflow_gtl_lora_slerpoff_s42` on UADFV only. The config is the stage-2 config with `test_datasets` cut to the UADFV entry. These per-video scores are compared with the committed stage-2 UADFV scores:
- **EXACT** if every video's |Δp| < 1e-4;
- **NEAR** if max |Δp| < 1e-2 and |ΔAUC| < 0.001;
- otherwise **FAIL**: the readout exits 3 and no rank-2/3 number is read.

Video keys and labels must match in both passing tiers.

**Statistic.**
- D17(a, s, r) is the MEAN-17 video AUC of the rank-r checkpoint of run `orthoflow_gtl_lora_slerp{a}_{s}`. It uses `slerp_readout.mean17_from_results` on `test_results.json` (the D17 list, KoDF read from KoDF-BM). Rank is by the file-name validation macro, so rank 1 follows the same rule as stage 2's `best_ckpt`.
- T(a, s) = the mean of D17(a, s, r) over r = 1, 2, 3.
- Δ̄_s = T(on, s) − T(off, s).
- m = the mean of Δ̄_s over the three seeds.

**Readings (fixed now, applied in this order):**
1. **SELECTION-ROBUST:** Δ̄_s < 0 at 3/3 seeds and m ≤ −0.23 pp.
2. **SELECTION-DRIVEN:** m > −0.15 pp.
3. **MIXED:** anything else.

Why these thresholds:
- **−0.23 pp** is half the selected-checkpoint effect (−0.46 pp). To "survive", at least half of the effect must remain, with the sign stage 2 showed at every seed.
- **−0.15 pp** is under a third of the effect, and under half of LoRA's April seed SD (0.33 pp). A drop that small cannot be told apart from seed noise at n = 3.
- **3/3:** stage 2's LoRA drop was negative at 3/3 seeds. A one-seed concentration (s42 dominated I3) should read MIXED, not ROBUST.

**Descriptive, not deciding:**
- rank-matched Δ_{s,r} = D17(on, s, r) − D17(off, s, r) for r = 2, 3 (6 cells, sign count);
- per arm, the selection gain D17(a, s, 1) − mean(D17(a, s, 2), D17(a, s, 3));
- per-dataset seed-mean of T(on) − T(off) on the 17 sets (sign count).

**What each reading means for the text:**
- **ROBUST:** "the LoRA drop with SLERP active does not depend on which of each run's three best validation checkpoints is scored."
- **DRIVEN:** "averaged over each run's three best validation checkpoints, LoRA with and without SLERP agree; the selected-checkpoint −0.46 pp reflects checkpoint selection on early validation peaks."
- **MIXED:** report m, Δ̄_s and the signs without a mechanism.

GSD-LoRA (16/17 sets lower, broad) and LN are not part of this amendment.

**Cost.** Stage-2 LoRA rescores took 1.63–2.03 h each (in-log timestamps), so 12 rescores take about 21 GPU-h, plus about 0.1 GPU-h for the gate. CDFv3 is read from poseidon's NFS share, so poseidon must be on.

**Rules.** Nothing is dropped after a number exists. A failed rescore is re-run, not excluded. If any of the 12 is missing, the readout exits 2.
